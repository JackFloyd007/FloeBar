# 双箭头持续出现：本机对照检查

2026-09-20 22:28–22:30，用户解锁后通过 CUA 实测。未修改图标顺序、系统偏好或显示缩放。

## 观察

1. FloeBar 1334 运行、系统收起：右侧显示系统双箭头和 FloeBar 固定图标。
2. 点系统双箭头：Notion、Figma、微信、ChatGPT、Spotlight、WPS 等溢出项目出现在屏幕中部左侧；右侧原有图标保留，中间存在大段不放图标的区域。
3. 正常退出 FloeBar：AX 树不再存在 Ice.ControlItem.Visible；刷新后没有 FloeBar 分隔控件，系统双箭头仍然存在。
4. 在 FloeBar 退出状态点击系统双箭头，仍能展开同批第三方项目；外观仍为中部两侧布局。
5. 已重新启动 FloeBar，并恢复系统收起状态。

system_profiler 确认唯一在线主显示器为内建 Liquid Retina，2560×1664。
CUA 菜单栏图像宽1470；收起时右侧图标/溢出入口大致占据 x850–1450，展开后新增图标大致出现在 x420–620。此为截图目测范围，不是 NSScreen safe-area 的精确测量。

## 判断与限制

当前现象符合内建刘海屏右侧容量不足、原生溢出跨到左侧显示的表现。整条菜单栏可见空白不能作为右侧可用空间的证明。退出 FloeBar 后问题仍存在，排除了“必须有当前 FloeBar 占位才能显示系统双箭头”的解释，但不能单靠退出实验排除系统历史布局残留。

没有进行减少其他应用图标、修改缩放、重启 MenuBarAgent 的对照，因此没有宣称已经证明所有不拥挤场景或彻底排除系统缺陷。此次没有发现需要改代码的直接证据。

Apple 27 官方说明：菜单栏空间不足时自动隐藏项目，并提供溢出入口。
https://support.apple.com/en-us/148830

产品限制仍成立：1334 普通模式是系统溢出入口的代理，保留 FloeBar 按钮会产生两个入口，并没有实现用户可任意指定隐藏成员、只留一个自定义入口的完整目标。
